# Robinhood Chain Lighter

### Delta-Neutral Perpetual Trading Bot

Автоматизация дельта-нейтральной торговли на
[Lighter в Robinhood Chain](https://robinhoodchain.lighter.xyz/)
с нескольких EVM-кошельков.

## Что это

Бот распределяет кошельки между сторонами `LONG` и `SHORT`, выравнивает
суммарный размер позиций и управляет полным торговым циклом:

```text
загрузка кошельков -> проверка прокси -> расчёт объёма
-> параллельное открытие LONG/SHORT -> удержание
-> параллельное закрытие -> отчёт PnL и объёма
```

Например, группа `[[3, 2]]` использует пять кошельков: три получают одну
сторону рынка, два — противоположную. Размеры распределяются так, чтобы общий
объём `LONG` был равен общему объёму `SHORT` после округления до шага выбранного
рынка.

Это уменьшает направленный риск движения выбранного актива, но не делает торговлю
безрисковой. Остаются funding, спред, проскальзывание, ошибки исполнения и риск
ликвидации.

## Возможности

- Дельта-нейтральная торговля настроенными perpetual-рынками к USDG.
- Параллельное открытие и закрытие позиций через `MARKET + IOC`.
- Альтернативный режим `leader-follower` с `POST_ONLY` лидером.
- Автоматическое выравнивание суммарных `LONG` и `SHORT`.
- Контроль максимального спреда и допустимого проскальзывания.
- Проверка фактических позиций после исполнения ордеров.
- Аварийное закрытие остаточной позиции при неполном хедже.
- Регистрация новых Lighter-аккаунтов после первого депозита.
- Автоматическое применение встроенного реферального кода.
- Пополнение Lighter всем доступным балансом USDG или заданной суммой.
- Проверка пула прокси с пропуском нерабочих и повторным использованием рабочих.
- Telegram-отчёты об открытии, закрытии, PnL, объёме и ошибках.
- Локальное шифрование приватных ключей, прокси и внутреннего кэша.
- Никаких CSV: пользователь заполняет только два текстовых файла.

## Режимы

После `npm start` программа показывает четыре рабочих режима:

```text
Выбери режим:
  1 = Дельта-нейтральная торговля
  2 = Закрыть все позиции
  3 = Проверить балансы
  4 = Регистрация + пополнение USDG
  0 = Выход
```

### 1. Дельта-нейтральная торговля

Формирует группу кошельков, рассчитывает одинаковый общий объём двух сторон,
открывает позиции, удерживает их выбранное время и закрывает. Количество циклов
задаётся через `TRADES_COUNT`.

### 2. Закрыть все позиции

Отменяет активные ордера и закрывает найденные позиции `reduce-only`. После
закрытия бот повторно проверяет каждый кошелёк и сообщает, если остался
ненулевой объём. В консоли и Telegram показываются фактические комиссии каждого
кошелька, а в итоге — общая комиссия и её ставка на торговый объём. Этот режим
также отправляет сигнал остановки процессу режима 1.

### 3. Проверить балансы

Показывает доступный баланс USDG и текущие позиции. Никаких торговых ордеров
режим не отправляет.

### 4. Регистрация + пополнение USDG

Для существующего аккаунта отправляет депозит и проверяет регистрацию. Для
нового кошелька сначала делает USDG-депозит, ждёт появления Lighter-аккаунта,
создаёт API-ключ и автоматически применяет встроенный реферальный код.

По умолчанию `DEPOSIT_ALL = True`: режим отправляет весь доступный USDG каждого
кошелька. Перед запуском обязательно проверь сеть, баланс и наличие нативного
токена для оплаты газа.

## Быстрый старт

### Требования

- Windows 10/11.
- Python 3.11 или новее.
- Node.js с `npm` — используется как удобная команда запуска.
- EVM-приватные ключи кошельков Robinhood Chain.
- HTTP/HTTPS-прокси по желанию; количество прокси может быть меньше числа кошельков.

Для работы нужны EVM-ключи длиной 64 шестнадцатеричных символа; префикс `0x`
необязателен.

### 1. Клонируй репозиторий

```powershell
git clone https://github.com/rud3wave/lighter-robinhood.git
cd lighter-robinhood
```

Команду `npm start` нужно выполнять именно здесь — рядом с `package.json`.

### 2. Установи зависимости

```powershell
npm install
```

Команда автоматически создаст `.venv`, установит Python-зависимости и
подготовит локальный `global.js`. Файлы `input_data/privatekeys.txt` и
`input_data/proxies.txt` уже лежат в репозитории пустыми; существующие данные не
перезаписываются.

### 3. Настрой `global.js`

Открой `global.js` и задай пароль:

```js
export const TELEGRAM = {
  token: '',
  chatId: 0,
};

export const ENCRYPTION_PASSWORD = 'длинный-уникальный-пароль';
```

Telegram можно оставить выключенным: пустой `token` и `chatId: 0`.

Важно: не меняй и не теряй `ENCRYPTION_PASSWORD` после первого запуска. Он
нужен для расшифровки локальных данных; открытая резервная копия ключей
программой не создаётся.

### 4. Добавь приватные ключи

Файл `input_data/privatekeys.txt`, один ключ на строку:

```text
0xPRIVATE_KEY_1
0xPRIVATE_KEY_2
0xPRIVATE_KEY_3
```

Комментарии с `#` и пустые строки игнорируются.

### 5. Добавь прокси

Файл `input_data/proxies.txt`, один прокси на строку:

```text
http://proxy-one.example:8000
http://proxy-two.example:8000
http://proxy-three.example:8000
```

Прокси с авторизацией также поддерживаются: логин и пароль указываются в
стандартном URL-формате.

При запуске бот проверяет все прокси и пропускает нерабочие. Рабочие прокси
распределяются между кошельками по кругу, поэтому их количество может быть меньше
количества приватных ключей и один прокси может использоваться несколькими
аккаунтами. Если рабочих прокси нет, бот продолжает работу через текущий IP.

При первом чтении оба входных файла автоматически шифруются на месте. В логах
отображаются только сокращённые публичные адреса, а данные авторизации прокси и
секретные значения скрываются.

### 6. Проверь настройки

Все пользовательские параметры находятся в `settings.py`. Текущий профиль:

```python
SHUFFLE_WALLETS = True
RETRY = 3
EXECUTION_MODE = "all-market"
TOKENS_TO_TRADE = ["ETH"]
POSITION_PERCENT = [85, 100]
TOKEN_LEVERAGE = {"ETH": [7, 10]}
GROUP_CONFIGS = [[3, 2]]
MAX_SPREAD = 0.03
SLIPPAGE = 0.02
HOLD_MINUTES = [720, 1440]
TRADES_COUNT = 3
DELAY_BETWEEN_TRADES = [10, 30]
DELAY_BETWEEN_WALLETS = [3, 8]
POLL_INTERVAL_SEC = 5
HEDGE_POLL_INTERVAL_MS = 300
MAKER_REQUOTE_INTERVAL_SEC = 20
MAKER_REQUOTE_THRESHOLD_PERCENT = 0.03
MAX_MAKER_WAIT_SEC = 180
MAX_HEDGE_RETRIES = 3
DEPOSIT_ALL = True
DEPOSIT_AMOUNT = [10, 10]
```

Этот профиль агрессивный: он использует 85–100% доступного баланса как маржу и
плечо 7–10x. Перед первым реальным запуском уменьши значения и проверь работу на
минимально допустимом размере.

### 7. Запусти

```powershell
npm start
```

Рекомендуемый порядок первого запуска:

1. Режим `3` — проверить адреса, прокси, балансы и позиции.
2. Режим `4` — зарегистрировать новые аккаунты и пополнить USDG.
3. Снова режим `3` — убедиться, что средства появились на Lighter.
4. Режим `1` — начать торговый цикл.

## Главные настройки

`SHUFFLE_WALLETS`
: Меняет порядок кошельков перед запуском. При `False` сохраняется порядок из
`privatekeys.txt`.

`RETRY`
: Число повторов неудачного торгового цикла и отправки Telegram-сообщения.

`EXECUTION_MODE`
: `all-market` открывает и закрывает все кошельки параллельно рыночными IOC-
ордерами. `leader-follower` использует `POST_ONLY` лидера и хеджирует его
фактические исполнения фолловерами.

`TOKENS_TO_TRADE`
: Один символ торгует только этот рынок. Из нескольких символов один выбирается
случайно для каждого цикла; каждому нужна собственная запись в `TOKEN_LEVERAGE`.

`POSITION_PERCENT`
: Процент доступного USDG, используемый как маржа. Значение выбирается случайно
из диапазона `[минимум, максимум]`.

`TOKEN_LEVERAGE`
: Диапазон плеча для каждого рынка. Биржевой максимум читается из метаданных
Lighter; превышение вызывает ошибку до торговли и не обрезается молча.

`GROUP_CONFIGS`
: Число кошельков по сторонам. Сумма каждой конфигурации должна совпадать с
числом готовых торговых кошельков. Из нескольких вариантов одинакового размера
один выбирается случайно для каждого цикла. Общий размер сторон выравнивается.

`MAX_SPREAD`
: Максимальный допустимый спред в процентах. `0.03` означает `0.03%`, не `3%`.

`SLIPPAGE`
: Защитное отклонение цены для `MARKET + IOC` в процентах.

`HOLD_MINUTES`
: Случайное время удержания в минутах. `[720, 1440]` — от 12 до 24 часов.
`[0, 0]` — удерживать до запуска режима 2 в другом процессе.

`TRADES_COUNT`
: Количество полных циклов `открытие -> удержание -> закрытие`.

`DELAY_BETWEEN_TRADES`
: Случайная пауза между циклами. `[0, 0]` отключает её.

`DELAY_BETWEEN_WALLETS`
: Реальная пауза между подготовкой торговых кошельков. Парные ордера после
подготовки остаются параллельными, чтобы не создавать открытую дельту.

`POLL_INTERVAL_SEC`
: Частота проверки спреда, удержания, повторов стратегии и появления fill.

`HEDGE_POLL_INTERVAL_MS`, `MAKER_REQUOTE_INTERVAL_SEC`,
`MAKER_REQUOTE_THRESHOLD_PERCENT`, `MAX_MAKER_WAIT_SEC`, `MAX_HEDGE_RETRIES`
: Управляют частичными maker-fill, перестановкой LIMIT и повторными хеджами в
режиме `leader-follower`.

`DEPOSIT_ALL`
: `True` отправляет весь доступный USDG. При `False` используется диапазон
`DEPOSIT_AMOUNT`, из которого выбирается случайная целая сумма USDG.

## Как исполняются ордера

### All-market — текущий режим

1. Бот получает order book через назначенный кошельку прокси или текущий IP.
2. Все `LONG` и `SHORT` отправляются параллельно через `asyncio.gather`.
3. Каждый ордер использует `MARKET + IOC` и защиту `SLIPPAGE`.
4. После исполнения бот читает реальные позиции каждого аккаунта.
5. При несовпадении размеров цикл считается ошибочным, остатки закрываются.

Нулевая торговая комиссия не означает нулевую стоимость: рыночные ордера могут
терять на спреде и проскальзывании, а открытые позиции участвуют в funding.
Тарифы и условия Lighter могут изменяться.

### Leader-follower — дополнительный режим

Лидер ставит `POST_ONLY` ордер. Каждый фактический partial fill сразу
распределяется между фолловерами через параллельные IOC-ордера. Зависший maker
перевыставляется, а после таймаута бот отменяет ордера и закрывает остаточный
риск.

## Логи

Торговая строка показывает кошелёк, сторону, размер позиции, количество
выбранного токена и защитную цену IOC. Например, для ETH:

```text
14:15:32 INFO 0xaFBc...1405 SHORT | $13.69 | 0.01 ETH | ENTRY 1874,78
```

`ENTRY` в этой строке — предельная цена IOC, рассчитанная с учётом `SLIPPAGE`.
Фактическая средняя цена исполнения может быть лучше и определяется сделками
Lighter.

## Telegram

Уведомления включаются в `global.js`:

```js
export const TELEGRAM = {
  token: 'BOT_TOKEN',
  chatId: 123456789,
};
```

Бот отправляет:

- запуск и остановку стратегии;
- открытые позиции и общий `LONG/SHORT`;
- закрытые позиции, PnL и торговый объём;
- стоимость на `$100k` оборота;
- результаты проверки балансов;
- результаты регистрации и депозитов;
- ошибки и повторные попытки.

Числа в консоли и Telegram показываются максимум с двумя знаками после запятой;
конечные нули не выводятся.

## Частые проблемы

### `npm error ENOENT: Could not read package.json`

Команда запущена не из папки проекта:

```powershell
cd lighter-robinhood
npm start
```

### `No module named ...`

Зависимости не установлены в `.venv`:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### Ошибка прокси

Бот проверяет весь пул, пропускает нерабочие адреса и распределяет оставшиеся по
кругу. Один рабочий прокси может использоваться несколькими кошельками. Если ни
одного рабочего прокси нет, бот продолжает через текущий IP.

### Баланс USDG равен нулю в режиме 4

Режим 4 проверяет USDG на L1-кошельке Robinhood Chain, а не торговый баланс
Lighter. Проверь сеть, адрес токена и кошелёк, на котором находятся средства.

### Не подходит пароль от хранилища

Используй тот же `ENCRYPTION_PASSWORD`, с которым файлы были впервые
зашифрованы. Смена пароля в `global.js` не перешифровывает существующие данные.

## Безопасность

- `global.js` и каталог `databases/` исключены из Git.
- В Git хранятся только пустые шаблоны входных файлов; после `npm install`
  локальные `privatekeys.txt` и `proxies.txt` помечаются как `skip-worktree`.
- Приватные ключи и прокси шифруются отдельно через AES-256-GCM.
- Ключ шифрования выводится из пароля через `scrypt`.
- Полные адреса, приватные ключи и данные авторизации прокси не печатаются.
- Подпись транзакций выполняется локально.

Перед публикацией репозитория всё равно проверь `git status` и убедись, что в
истории Git никогда не было реальных ключей, токенов Telegram или прокси.

## Важно

Этот проект отправляет реальные торговые ордера и блокчейн-транзакции. Автор не
гарантирует прибыль, начисление поинтов, конкретный множитель наград или
отсутствие убытков. Использование API не имитирует нативный Robinhood Wallet и
само по себе не гарантирует `x2`.

Программное обеспечение предоставляется «как есть». Проверяй настройки на малых
суммах и используй только те средства, потерю которых можешь позволить.
